# BoundaryLens Prototype Explanation

This document explains the interactive **BoundaryLens Web UI (Frontend)**, detailing how it works, what each component does, and how to effectively demo it to judges or stakeholders. Reading this document is sufficient to completely understand the user-facing application.

---

## 1. Overview & Tech Stack

The frontend is a lightweight, hardware-accelerated 3D mapping application designed to visualize the outputs of the BoundaryLens data pipeline.

**Tech Stack**:
- **Vanilla HTML / CSS / JS**: We deliberately avoided complex frameworks (like React/Next.js) to ensure the prototype is incredibly fast, easy to deploy locally, and has zero build-step dependencies.
- **MapLibre GL JS**: An open-source, WebGL-based mapping library used to render vector tiles and hardware-accelerated 3D polygons.
- **Data Source**: It directly reads the `frontend/data/buildings_3d.geojson` file generated by the backend pipeline.

---

## 2. User Interface Layout

When you open `http://localhost:8000`, the application is split into two primary areas:

### A. The 3D Map Canvas (Right Side)
- A dynamic, interactive map of Bengaluru Urban.
- **Base Map**: A dark-themed CartoDB base layer that makes the 3D structures pop.
- **2D Parcels (Ground Layer)**: The legal cadastral parcel boundaries are rendered flat on the ground as subtle dark polygons with white borders.
- **3D Buildings (Extruded Layer)**: The building footprints are extruded into 3D volumes. The height of the 3D mesh is driven dynamically by the `building_height_m` attribute calculated in our pipeline.

### B. The Glassmorphic Sidebar (Left Side)
A modern, translucent glass UI panel containing:
1. **Global Statistics**: Displays total loaded buildings (2,734) and cadastral parcels (78).
2. **Match Status Legend**: Explains the color coding of the 3D buildings (Green, Amber, Red).
3. **Selected Structure Property Card**: When a building is clicked, this card populates with all the specific details of that building.

---

## 3. How Visual 3D Extrusion & Color Coding Works

The most striking feature of the prototype is how the data visually communicates spatial and legal reality.

### 3D Extrusion Logic
In `frontend/app.js`, MapLibre renders the `buildings-3d-layer` using `fill-extrusion`:
- `fill-extrusion-height`: Bound directly to the `building_height_m` property. If a building is assigned 14m by our satellite dataset, MapLibre physically draws a 14-meter tall 3D block on the screen.
- `fill-extrusion-base`: Bound to `0` (or `ground_elevation_m` in true 3D terrain mode).

### Color Coding Logic (The Traffic Light System)
Buildings are instantly color-coded based on the topological match status calculated in the backend:
- 🟢 **GREEN (`CONTAINED`)**: The building footprint is >95% inside the cadastral parcel boundary. It is structurally compliant.
- 🟡 **AMBER (`MAJORITY`)**: The building is mostly inside, but touches the boundary slightly.
- 🔴 **RED (`CONFLICT` / `BOUNDARY_OVERLAP`)**: The building severely encroaches over the property line, or straddles multiple properties.

## 4. The Property Card & Human-in-the-Loop Workflow

When you click on any building, the Property Card in the sidebar updates. This is where the core SIH26011 problem statement is addressed.

### Data Displayed:
- **ULPIN / Parcel ID**: Which 2D parcel this building is linked to.
- **Match Status**: Contained, Majority, or Conflict.
- **Height (m) / Floors**: E.g., `14m (4 Floors)`. Proof of multi-storey 3D delineation!
- **Data Source**: Explicit provenance (e.g., `GOOGLE_OPEN_BUILDINGS_2.5D`). This satisfies the requirement not to fabricate authoritative data.
- **Proposed 3D ULPIN**: The hierarchical identifier (e.g., `IN-KA-BLR-P78-B12-F3`).

### The Reviewer Audit Gate (Project Rule 8)
At the bottom of the card are four buttons: `[APPROVE]`, `[CORRECT]`, `[REJECT]`, `[MARK UNRESOLVED]`.
- **How it works**: BoundaryLens is designed such that **AI assists, but does not adjudicate legal rights**. 
- If our Fusion Engine flagged a building as `HUMAN_VERIFICATION_REQUIRED` (e.g., because it was colored Red, or the AI flagged an anomaly), a human reviewer must make the final call.
- Clicking one of these buttons instantly changes the Verification Gate status on the UI and logs an Audit Action.

## 5. How to Demo to Judges (Step-by-Step)

If you are presenting this prototype, follow this script:

1. **Load the Map**: Start the UI. Point out the dark base map and the 3D extruded buildings showing the true skyline of the pilot area.
2. **Explain the Colors**: Explain that the colors aren't random. Green means the building perfectly fits the property boundary; Red means encroachment.
3. **Show Multi-Storey Data**: Click a Green building. Show the sidebar. Point out the `Height / Floors` row. State: *"We aren't just doing 2D maps; we are delineating vertical floors using satellite height estimation."*
4. **Show the 3D ULPIN**: Point to the Proposed 3D ULPIN in the sidebar. State: *"Here is the hierarchical identifier linking the parcel to the building to the individual floors, directly solving the SIH problem statement."*
5. **Show the Conflict Resolution**: Find a Red building and click it. Point out that the Verification Gate says `HUMAN_VERIFICATION_REQUIRED`. State: *"We don't let AI overwrite legal property lines. Conflicts are routed to a human."*
6. **Trigger an Audit Log**: Click the `[REJECT]` button in the Reviewer Audit Gate. Watch the status change live and the alert popup appear logging the audit action. State: *"Every reviewer decision is immutably logged for legal auditability."*
